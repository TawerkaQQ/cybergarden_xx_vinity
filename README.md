# Vinity — проверенные данные из научных статей

Кейс 5 ЮФУ и ВИНИТИ РАН, Cyber Garden 2026.

Система превращает научные статьи в PDF в набор данных в формате сдачи: извлекает числовые значения и описание образцов, приводит их к единицам области, привязывает каждое число к странице и дословной цитате, отмечает повторы одного значения, проверяет данные на согласованность и показывает всё это в интерфейсе с подсветкой места в PDF.

## Возможности

- **Извлечение** из текста, таблиц и подписей к рисункам: публикация, материалы, приборы, слои, условия измерения и все упоминания значений показателей.
- **Привязка к месту:** у каждого значения — страница, раздел, таблица или рисунок и цитата, которая дословно есть на странице. Для подсветки — координаты цитаты и самого числа на странице PDF.
- **Нормализация:** показатели к именам и целевым единицам области (1197 mV → 1.197 V, FF 0.71 → 71 %), разные написания единиц — к одному, числа вида «1,322» и «14.4 × 10²».
- **Повторы:** одно значение того же образца, упомянутое в аннотации, тексте и таблице — в том числе разными словами («efficiency», «PCE», «power conversion efficiency»), — связывается через `duplicate_of` с основной записью из таблицы или рисунка. Значения из других работ помечаются `cited` со ссылкой. Сервер интерфейса дополнительно находит одни и те же результаты в разных статьях.
- **Проверки достоверности** (`issues.csv`) — все правила раздела 3.3: PCE против Voc·Jsc·FF/Pin (`jv_consistency`), Jsc против Jsc по EQE (`eqe_consistency`), Voc ниже ширины запрещённой зоны поглотителя (`voc_limit`), индекс гистерезиса против PCE обратного и прямого хода (`hysteresis_index`), среднее против лучшего (`champion_vs_mean`), разумные диапазоны (`range`), противоречия между упоминаниями одного значения (`contradiction`). Физика и пороги — в профиле, в коде только общие виды правил.
- **Интерфейс:** статьи, поиск и фильтры по значениям, карточка значения с местом в PDF, замечания с доказательствами, проверка значений референтом, качество против эталона, паспорт данных, вопросы по статьям с источниками, загрузка и обработка новой статьи, подключение новой области без кода.
- **Один движок для разных областей:** что извлекать, задаёт профиль области. Новая область — новый профиль, без изменения кода.

## Устройство

```
data/<профиль>/<набор>/*.pdf
        │
        ▼  pages      текст страниц (pypdf)                       → work/<профиль>/pages/<id>.json
        ▼  extract    модель: описание образцов и все упоминания   → work/<профиль>/extract/<id>.json
        ▼  assemble   таблицы сдачи, нормализация, цитаты,         → out/<профиль>/<набор>/*.csv
                      повторы, подсветка, проверки                   out/<профиль>/<набор>/articles/<id>.json
        ▼  score      точность и полнота против эталона
```

| Папка | Что в ней |
|---|---|
| `pipeline/` | конвейер на Python: `domain` — модели, профиль, промпты, сборка, проверки, оценка; `application` — сценарии; `infrastructure` — pypdf, PyMuPDF, клиент модели, кэш, файлы |
| `profiles/` | профили областей: `solar` (тонкоплёночные солнечные элементы), `rag` (Retrieval-Augmented Generation), `generic` (любая статья) |
| `kt/` (ветка `feature/kt`) | сервер и интерфейс: сайт и desktop-приложение, руководство пользователя `kt/docs/manual.md` |
| `rag/` | поиск по статьям с ответами модели на вопросы (Qdrant, `docker-compose.yml`, настройки в `.env.example`) |

**Профиль** — `profiles/<профиль>/profile.json` и `rules.md`. В нём таблицы сдачи и их колонки, словари допустимых значений, единицы и переводы между ними, оцениваемые показатели, разумные диапазоны, правила повторов, режимы сравнения с эталоном и проверки достоверности, а в `rules.md` — правила разметки словами. Из профиля строятся промпт и JSON-схема ответа модели, сборка таблиц, проверки и оценка.

**Извлечение моделью** — запросы к модели в формате OpenAI API с ответом строго по JSON-схеме:

1. публикация и записи таблиц (материалы, приборы, слои, измерения);
2. все упоминания значений в тексте;
3. список таблиц со значениями и, если таблица выписана неполно, отдельный запрос по ней;
4. значения из других работ.

## Требования

- Python 3.12 и [uv](https://docs.astral.sh/uv/).
- Сервер с GPU и vLLM: модель Qwen3.6-35B-A3B, сборка FP8 (`Qwen/Qwen3.6-35B-A3B-FP8`, ~35 ГБ весов) — например, одна карта на 96 ГБ; или NVFP4 (`nvidia/Qwen3.6-35B-A3B-NVFP4`) на карте 32 ГБ.
- Для интерфейса — Java (JDK) для сборки через Gradle wrapper из `kt/`; готовая сборка `kt/scripts/release.ps1` содержит Java внутри.

## Модель

```bash
uv venv --python 3.12 ~/vllm/.venv && source ~/vllm/.venv/bin/activate
uv pip install -U "vllm>=0.31" --torch-backend auto

vllm serve Qwen/Qwen3.6-35B-A3B-FP8 \
  --served-model-name qwen3.6-35b-a3b-fp8 \
  --max-model-len 131072 --kv-cache-dtype fp8 --max-num-seqs 16 \
  --enable-prefix-caching --reasoning-parser qwen3 \
  --default-chat-template-kwargs '{"enable_thinking": false}' \
  --structured-outputs-config '{"backend": "xgrammar"}' \
  --host 127.0.0.1 --port 8000
```

Не включайте `disable_any_whitespace`: модель пишет JSON с переносами строк, и запрет пробелов снижает качество, а ответы-списки может сделать пустыми. Если сервер открыт наружу, задайте ключ: `export VLLM_API_KEY=…` перед запуском и тот же ключ в `OPENAI_API_KEY` у конвейера.

Проверка: `curl -s http://127.0.0.1:8000/v1/models`.

## Запуск конвейера

Из корня репозитория. Окружение `uv` собирает сам:

```bash
export OPENAI_API_KEY=none
P="uv run --python 3.12 --with-editable ./pipeline python -m pipeline"
M="--base-url http://127.0.0.1:8000/v1 --model qwen3.6-35b-a3b-fp8 --workers 16 --max-tokens 32768"

$P run --profile solar --set dev  $M          # вся цепочка и оценка против dev_gold
$P run --profile solar --set test $M          # сдача: out/solar/test/
python data/solar/tools/check_submission.py out/solar/test data/solar/test
```

Без `uv`: `python3.12 -m venv pipeline/.venv && pipeline/.venv/bin/pip install -r pipeline/requirements.txt -e ./pipeline`, затем `pipeline/.venv/bin/python -m pipeline …`.

| Команда | Что делает |
|---|---|
| `pages --profile P --set S` | текст страниц PDF |
| `extract --profile P --set S [--runs N]` | извлечение моделью; `--runs N` — N запусков, остаются значения, найденные большинством |
| `assemble --profile P --set S` | таблицы сдачи, подсветка, JSON статей, проверки |
| `score --profile P --set S [--details]` | точность и полнота против `data/P/S_gold` |
| `run --profile P --set S` | `pages`, `extract`, `assemble` и `score`, если есть эталон |
| `article <pdf> --profile P` | одна статья: текст, извлечение, пересборка набора её папки; так обрабатывает загрузку сервер |
| `check <папка> --profile P --out <папка>` | проверки достоверности по таблицам любой папки, например по эталону |

Все команды принимают `--only <id …>` — обработать только эти статьи.

## Интерфейс

Модуль `kt/` (ветка `feature/kt`): сервер на Ktor и интерфейс на Compose Multiplatform — сайт и desktop-приложение из одного кода. Сервер читает `profiles/`, `data/`, `work/` и `out/` этого репозитория, а новые PDF обрабатывает командами конвейера `pages`, `extract`, `assemble`. Подробное описание экранов — `kt/docs/manual.md`.

### Запуск

Windows, из папки `kt`:

```
scripts\start.ps1          сборка и запуск сервера с сайтом, ~5 минут; -Dev — быстрая сборка без оптимизации
scripts\stop.ps1           остановить
scripts\release.ps1        готовая сборка в kt\build\release\: server.cmd, desktop.cmd (Java внутри), vinity.properties
```

Linux и macOS, из папки `kt`:

```bash
./gradlew :app:wasmJsBrowserDistribution :server:installDist
OPENAI_BASE_URL=http://127.0.0.1:8000/v1 OPENAI_API_KEY=none ./server/build/install/server/bin/server
./gradlew :app:run -Pvinity.api=http://localhost:8081      # desktop-приложение
```

Сайт открывается на `http://localhost:8081`. Чтобы сервер мог обрабатывать загруженные PDF, нужно окружение конвейера `pipeline/.venv` (см. «Запуск конвейера») и адрес модели.

### Настройки

Файл `kt/local.properties` (для `start.ps1`) или `vinity.properties` рядом с сервером; любой ключ можно задать и как `-Dvinity.<ключ>=…`.

| Ключ | Переменная окружения | Что задаёт |
|---|---|---|
| `root` | — | корень репозитория с `profiles`, `data`, `work`, `out`, `pipeline`; по умолчанию папка выше `kt` |
| `port` | — | порт сервера, по умолчанию 8081 |
| `model.url` | `OPENAI_BASE_URL` | адрес модели для обработки новых PDF и вопросов по статьям |
| `model.name` | `OPENAI_MODEL` | имя модели; если не задано, сервер берёт первую из `/v1/models` |
| `model.key` | `OPENAI_API_KEY` | ключ модели |
| `rag.url` | `RAG_URL` | адрес модуля `rag/`: вопросы по статьям уходят в него |
| `rag.python` | — | Python модуля `rag/` для режима «RAG-система»; по умолчанию `rag/.venv` |
| `rag.qdrant` | `QDRANT_URL` | адрес Qdrant для режима «RAG-система»; по умолчанию из `rag/.env` или `http://127.0.0.1:6333` |
| `python` | — | Python конвейера; по умолчанию `pipeline/.venv` |
| `web` | — | папка собранного сайта; по умолчанию `kt/app/build/dist/wasmJs/productionExecutable` |

Без адреса модели сайт работает со всеми готовыми данными, но новые PDF не обрабатываются.

### Что в интерфейсе

В топбаре два режима: **«Статьи»** — экраны ниже, и **«RAG-система»** — чат с модулем `rag/`.

| Экран | Что умеет |
|---|---|
| **Статьи** | набор (область, `dev`/`test`/загруженные) и источник (результат системы или эталон экспертов); поиск по названию, ID, DOI; группы «есть замечания», «без замечаний», «не обработаны», «вне области»; загрузка PDF с очередью обработки |
| **Страница статьи** | значения по записям или по показателям, показ повторов, только с замечаниями; сравнение с экспертами: лишнее, «сверх эталона» с дословной цитатой, пропущенное; замечания; записи (приборы, материалы, измерения); сведения; «те же результаты» в других статьях |
| **Карточка значения** | число в единицах области и как оно записано в статье, нормализация «в статье → у нас», место (страница, таблица, рисунок, раздел), найдена ли цитата, страница PDF с рамкой; повторы, происхождение, есть ли у экспертов; проверка референтом: подтвердить, исправить, отклонить |
| **Карточка замечания** | правило, числа с обеих сторон, страницы с подсветкой спорного места; подтвердить или снять с причиной |
| **Просмотр PDF** | листание, масштаб, «все находки статьи» на странице: синяя рамка — значение, красная — замечание |
| **Все значения** | таблица всех значений набора: поиск по статье, записи, числу и цитате; фильтры по показателю, источнику (таблица, рисунок, текст), статусу проверки, диапазону с гистограммой, «только с замечаниями», «без повторов»; сортировка; выгрузка CSV в формате сдачи |
| **Вопрос по статьям** | ответ модели только по найденным фрагментам статей, с номерами источников и переходом на страницу или значение |
| **Обзор** | графики из профиля: для `solar` — Voc против ширины запрещённой зоны и лучший КПД по статьям |
| **Качество** | точность и полнота (строгое и мягкое сравнение, все упоминания или только основные, по показателям); связь с местом в статье (доля найденных цитат); нормализация; проверка достоверности (совпадения с замечаниями экспертов по правилам); паспорт данных |
| **Паспорт данных** | что в наборе, откуда он и как получить заново: состав, значения, проверки, происхождение (sha256 каждой PDF, хэш манифеста, модель и версия промпта, хэш профиля), точность и полнота, выходные файлы со строками, размером и sha256, команды воспроизведения; выгрузка в JSON |
| **RAG-система** | отдельный режим без других вкладок: вопрос к базе Qdrant — по статьям PDF или по таблицам CSV, с выбором числа фрагментов; ответ «из базы статей» с номерами источников и отдельный ответ «из интернета» со ссылками на страницы и временем получения; слева история запросов — переход к ответу, повтор, очистка. Сервер вызывает `rag/api.py` (окружение `rag/.venv` из `rag/requirements.txt`), адрес модели берёт из `model.url` |
| **Области** | подключённые профили, подключение новой области загрузкой `profile.json` и `rules.md`, сценарий демо |

Сервер сам перепроверяет любой загруженный набор: связывает повторы, ищет противоречия, несогласованные повторы, метрики вне шкалы, проценты вместо процентных пунктов (`rag`) и одни и те же результаты в разных статьях. Его замечания идут с номерами на «S».

## Соответствие критериям

| Критерий | Чем закрыт |
|---|---|
| Точность и полнота извлечения | `score` и вкладка «Качество»: `loose` и `strict`, по показателям; цифры — в разделе ниже |
| Значения сверх эталона со ссылками на текст | у каждого значения страница и дословная цитата; в интерфейсе — «сверх эталона» с найденной цитатой, в паспорте — их число |
| Откуда взято значение | `source_page`, раздел, таблица, рисунок, цитата; координаты подсветки в `articles/<id>.json`; страница PDF с рамкой в карточке |
| Повторы одного значения | `duplicate_of` с основной записью из таблицы или рисунка; фильтр «без повторов» |
| Одно значение разными словами и у разных авторов | показатели и единицы приводятся к каноническим; повторы связываются независимо от формулировки; чужие результаты — `cited` со ссылкой; одни и те же результаты в разных статьях — «Есть в …» и «те же результаты» |
| Нормализация | целевые единицы профиля, вывод единицы по разумному диапазону, «в статье → у нас» в карточке и во вкладке «Нормализация» |
| Проверка достоверности | `issues.csv` по семи правилам раздела 3.3 и проверки сервера; карточка замечания с обеими цитатами |
| Интерфейс: поиск, фильтры, карточка с местом | экраны «Статьи», «Все значения», карточка значения, просмотр PDF |
| Паспорт данных и воспроизводимость | паспорт в интерфейсе с выгрузкой JSON; одна команда `run`; кэш по sha256 PDF, версии промпта и модели; закреплённые зависимости |

## Качество на dev

Сравнение `out/solar/dev/results.csv` с `data/solar/dev_gold/results.csv` командой `score`: 21 статья, 626 значений 11 оцениваемых показателей. Строка засчитывается, если совпали показатель, значение в целевых единицах и источник (свой или чужой результат); каждая строка эталона засчитывается один раз.

Модель FP8, один запуск, промпт `solar-6-00a7beb5`:

| Режим | Точность | Полнота | F1 |
|---|---|---|---|
| **`loose`**: показатель, значение, источник | 75,8 % | 88,0 % | **81,4 %** |
| `loose` без повторов | 81,8 % | 88,6 % | 85,0 % |
| `strict`: ещё агрегация и страница | 60,2 % | 70,0 % | 64,7 % |

- Проверка организаторов `check_submission.py`: 0 ошибок, все цитаты найдены на своих страницах.
- Страница верна у 96 % значений, совпавших с эталоном.
- Модель недетерминирована даже при температуре 0: F1 одного запуска колеблется в пределах ±2–3 пунктов.
- Значения сверх эталона — в основном повторы верных чисел и числа из других работ, которые эксперт не записал; у всех есть страница и дословная цитата.

## Воспроизводимость

- Вся цепочка — одна команда `run`.
- Ответы модели кэшируются в `pipeline/.cache/<sha256 PDF>/<версия промпта>-<модель>[-runN]/`. Версия промпта — `<профиль>-<версия движка>-<хэш промптов и схем>`: правка профиля или промпта меняет версию, и ответы запрашиваются заново; повторный запуск с той же версией идёт из кэша.
- Зависимости закреплены в `pipeline/requirements.txt` и `uv.lock`.
- Паспорт данных в интерфейсе показывает sha256 каждой статьи, версию промпта и модель, хэш профиля, файлы результата с хэшами и числом строк.

## Ограничения

- Текст страниц берётся из текстового слоя PDF; значения, которые есть только на растровых рисунках, не извлекаются.
- Агрегация (лучший прибор, среднее) в эталоне размечена непоследовательно, поэтому оценка `strict` заметно ниже `loose`.
- Конвейер связывает повторы в пределах статьи; совпадения между статьями находит сервер интерфейса, а в таблицах сдачи они не отмечаются.
- Проверки находят только числовые несогласованности; противоречия в описании (материалы, структура прибора) не проверяются.
