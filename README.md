# Vinity — проверенные данные из научных статей

Кейс 5 ЮФУ и ВИНИТИ РАН, Cyber Garden 2026.

Система превращает научные статьи в PDF в набор данных в формате сдачи: извлекает числовые значения и описание образцов, приводит их к единицам области, привязывает каждое число к странице и дословной цитате, отмечает повторы одного значения, проверяет данные на согласованность и показывает всё это в интерфейсе с подсветкой места в PDF.

## Возможности

- **Извлечение** из текста, таблиц и подписей к рисункам: публикация, материалы, приборы, слои, условия измерения и все упоминания значений показателей.
- **Привязка к месту:** у каждого значения — страница, раздел, таблица или рисунок и цитата, которая дословно есть на странице. Для подсветки — координаты цитаты и самого числа на странице PDF.
- **Нормализация:** показатели к именам и целевым единицам области (1197 mV → 1.197 V, FF 0.71 → 71 %), разные написания единиц — к одному, числа вида «1,322» и «14.4 × 10²».
- **Повторы:** одно значение того же образца, упомянутое в аннотации, тексте и таблице, связывается через `duplicate_of` с основной записью из таблицы или рисунка. Значения из других работ помечаются `cited` со ссылкой.
- **Проверки достоверности** (`issues.csv`): PCE против Voc·Jsc·FF/Pin, Jsc против Jsc по EQE, среднее против лучшего, разумные диапазоны, противоречия между упоминаниями одного значения.
- **Интерфейс:** статьи, поиск и фильтры по значениям, карточка значения с местом в PDF, замечания с доказательствами, качество против эталона, паспорт данных, загрузка новой статьи.
- **Один движок для разных областей:** что извлекать, задаёт профиль области. Новая область — новый профиль, без изменения кода.

## Устройство

```
data/<профиль>/<набор>/*.pdf
        │
        ▼  pages      текст страниц (pypdf)                       → work/<профиль>/pages/<id>.json
        ▼  extract    модель: описание образцов и все упоминания   → work/<профиль>/extract/<id>.json
        ▼  assemble   таблицы сдачи, нормализация, цитаты,         → out/<профиль>/<набор>/*.csv
                      повторы, подсветка, проверки                   out/<профиль>/<набор>/articles/<id>.json
        ▼  score      точность и полнота против эталона
```

| Папка | Что в ней |
|---|---|
| `pipeline/` | конвейер на Python: `domain` — модели, профиль, промпты, сборка, проверки, оценка; `application` — сценарии; `infrastructure` — pypdf, PyMuPDF, клиент модели, кэш, файлы |
| `profiles/` | профили областей: `solar` (тонкоплёночные солнечные элементы), `rag` (Retrieval-Augmented Generation), `generic` (любая статья) |
| `kt/` (ветка `feature/kt`) | сервер и интерфейс: сайт и desktop-приложение, руководство пользователя `kt/docs/manual.md` |
| `rag/` | поиск по статьям с ответами модели на вопросы (Qdrant, `docker-compose.yml`, настройки в `.env.example`) |

**Профиль** — `profiles/<профиль>/profile.json` и `rules.md`. В нём таблицы сдачи и их колонки, словари допустимых значений, единицы и переводы между ними, оцениваемые показатели, разумные диапазоны, правила повторов, режимы сравнения с эталоном и проверки достоверности, а в `rules.md` — правила разметки словами. Из профиля строятся промпт и JSON-схема ответа модели, сборка таблиц, проверки и оценка.

**Извлечение моделью** — запросы к модели в формате OpenAI API с ответом строго по JSON-схеме:

1. публикация и записи таблиц (материалы, приборы, слои, измерения);
2. все упоминания значений в тексте;
3. список таблиц со значениями и, если таблица выписана неполно, отдельный запрос по ней;
4. значения из других работ.

## Требования

- Python 3.12 и [uv](https://docs.astral.sh/uv/).
- Сервер с GPU и vLLM: модель Qwen3.6-35B-A3B, сборка FP8 (`Qwen/Qwen3.6-35B-A3B-FP8`, ~35 ГБ весов) — например, одна карта на 96 ГБ; или NVFP4 (`nvidia/Qwen3.6-35B-A3B-NVFP4`) на карте 32 ГБ.
- Для интерфейса — Java (JDK) для сборки через Gradle wrapper из `kt/`; готовая сборка `kt/scripts/release.ps1` содержит Java внутри.

## Данные

Папка `data/` в git не входит. Материалы области 1 раскладываются так:


Из архива организаторов:

```bash

mkdir -p data/solar && cp -r /tmp/case1/Кейс5_область1_участникам/* data/solar/
```

## Модель

```bash
uv venv --python 3.12 ~/vllm/.venv && source ~/vllm/.venv/bin/activate
uv pip install -U "vllm>=0.31" --torch-backend auto

vllm serve Qwen/Qwen3.6-35B-A3B-FP8 \
  --served-model-name qwen3.6-35b-a3b-fp8 \
  --max-model-len 131072 --kv-cache-dtype fp8 --max-num-seqs 16 \
  --enable-prefix-caching --reasoning-parser qwen3 \
  --default-chat-template-kwargs '{"enable_thinking": false}' \
  --structured-outputs-config '{"backend": "xgrammar"}' \
  --host 127.0.0.1 --port 8000
```

Не включайте `disable_any_whitespace`: модель пишет JSON с переносами строк, и запрет пробелов снижает качество, а ответы-списки может сделать пустыми. Если сервер открыт наружу, задайте ключ: `export VLLM_API_KEY=…` перед запуском и тот же ключ в `OPENAI_API_KEY` у конвейера.

Проверка: `curl -s http://127.0.0.1:8000/v1/models`.

## Запуск конвейера

Из корня репозитория. Окружение `uv` собирает сам:

```bash
export OPENAI_API_KEY=none
P="uv run --python 3.12 --with-editable ./pipeline python -m pipeline"
M="--base-url http://127.0.0.1:8000/v1 --model qwen3.6-35b-a3b-fp8 --workers 16 --max-tokens 32768"

$P run --profile solar --set dev  $M          # вся цепочка и оценка против dev_gold
$P run --profile solar --set test $M          # сдача: out/solar/test/
python data/solar/tools/check_submission.py out/solar/test data/solar/test
```

Без `uv`: `python3.12 -m venv pipeline/.venv && pipeline/.venv/bin/pip install -r pipeline/requirements.txt -e ./pipeline`, затем `pipeline/.venv/bin/python -m pipeline …`.

| Команда | Что делает |
|---|---|
| `pages --profile P --set S` | текст страниц PDF |
| `extract --profile P --set S [--runs N]` | извлечение моделью; `--runs N` — N запусков, остаются значения, найденные большинством |
| `assemble --profile P --set S` | таблицы сдачи, подсветка, JSON статей, проверки |
| `score --profile P --set S [--details]` | точность и полнота против `data/P/S_gold` |
| `run --profile P --set S` | `pages`, `extract`, `assemble` и `score`, если есть эталон |
| `article <pdf> --profile P` | одна статья: текст, извлечение, пересборка набора её папки; так обрабатывает загрузку сервер |
| `check <папка> --profile P --out <папка>` | проверки достоверности по таблицам любой папки, например по эталону |

Все команды принимают `--only <id …>` — обработать только эти статьи.

## Интерфейс

Модуль `kt/` в ветке `feature/kt`: сервер на Ktor и интерфейс на Compose Multiplatform — сайт и desktop-приложение из одного кода. Читает `data/`, `work/`, `out/` и профили этого репозитория, новые PDF обрабатывает командами конвейера. Запуск, настройки и описание экранов — в `kt/docs/manual.md`; по умолчанию сайт открывается на `http://localhost:8081`.

## Качество на dev

Сравнение `out/solar/dev/results.csv` с `data/solar/dev_gold/results.csv` командой `score`: 21 статья, 626 значений 11 оцениваемых показателей. Строка засчитывается, если совпали показатель, значение в целевых единицах и источник (свой или чужой результат); каждая строка эталона засчитывается один раз.

Модель FP8, один запуск, промпт `solar-6-00a7beb5`:

| Режим | Точность | Полнота | F1 |
|---|---|---|---|
| **`loose`**: показатель, значение, источник | 75,8 % | 88,0 % | **81,4 %** |
| `loose` без повторов | 81,8 % | 88,6 % | 85,0 % |
| `strict`: ещё агрегация и страница | 60,2 % | 70,0 % | 64,7 % |

- Проверка организаторов `check_submission.py`: 0 ошибок, все цитаты найдены на своих страницах.
- Страница верна у 96 % значений, совпавших с эталоном.
- Модель недетерминирована даже при температуре 0: F1 одного запуска колеблется в пределах ±2–3 пунктов.
- Значения сверх эталона — в основном повторы верных чисел и числа из других работ, которые эксперт не записал; у всех есть страница и дословная цитата.

## Воспроизводимость

- Вся цепочка — одна команда `run`.
- Ответы модели кэшируются в `pipeline/.cache/<sha256 PDF>/<версия промпта>-<модель>[-runN]/`. Версия промпта — `<профиль>-<версия движка>-<хэш промптов и схем>`: правка профиля или промпта меняет версию, и ответы запрашиваются заново; повторный запуск с той же версией идёт из кэша.
- Зависимости закреплены в `pipeline/requirements.txt` и `uv.lock`.
- Паспорт данных в интерфейсе показывает sha256 каждой статьи, версию промпта и модель, хэш профиля, файлы результата с хэшами и числом строк.

## Ограничения

- Текст страниц берётся из текстового слоя PDF; значения, которые есть только на растровых рисунках, не извлекаются.
- Агрегация (лучший прибор, среднее) в эталоне размечена непоследовательно, поэтому оценка `strict` заметно ниже `loose`.
- Одинаковые значения связываются как повторы в пределах статьи, но не между статьями.
- Проверки `voc_limit` и `hysteresis_index` из профиля `solar` пока не реализованы.
