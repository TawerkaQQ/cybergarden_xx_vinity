# Vinity — руководство пользователя

Vinity превращает научные статьи в PDF в проверенный набор данных. Система извлекает числовые значения из текста, таблиц и подписей к рисункам, приводит их к единицам области и привязывает каждое число к дословной цитате на странице. Затем она проверяет данные на согласованность. Сайт нужен, чтобы смотреть результат, сверять его с эталоном экспертов, разбирать замечания, задавать вопросы по статьям и выгружать набор вместе с паспортом.

## Запуск

Сайт и сервер запускаются одной командой из папки `kt`:

```
scripts\start.ps1            обычная сборка, около 5 минут: для демонстрации
scripts\start.ps1 -Dev       быстрая сборка без оптимизации, около минуты: для проверки правок
scripts\stop.ps1             остановить сервер
```

После запуска сайт открывается по адресу `http://localhost:8081`. Сервер работает в фоне, лог пишется в `kt\build\logs\server.log`.

Настройки лежат в `kt\local.properties`. Этот файл не попадает в git:

| Ключ | Зачем |
|---|---|
| `model.url` | адрес модели, совместимой с OpenAI API. Нужен для обработки загруженных PDF и для вопросов по статьям. Имя модели сервер узнаёт сам |
| `rag.url` | адрес модуля РАГ. Если он задан, вопросы по статьям уходят в этот модуль |

Без `model.url` сайт работает со всеми готовыми данными, но новые PDF не обрабатываются, а на вопросы система отвечает только найденными фрагментами.

## Основные понятия

| Понятие | Что это |
|---|---|
| **Область** | Предметная область, описанная профилем `profiles/<имя>/profile.json`: таблицы, показатели, единицы, словари и правила проверки. Сейчас подключены «Тонкоплёночные солнечные элементы» (`solar`), «Retrieval-Augmented Generation» (`rag`) и «Любая научная статья» (`generic`). Код под область не пишется |
| **Набор** | Группа статей одной области: `dev`, `test` и «загруженные» — статьи, загруженные через сайт |
| **Источник** | Откуда берутся значения набора: **результат системы** (`out/<область>/<набор>`) или **эталон экспертов** (`data/<область>/<набор>_gold`). Если есть оба, их можно сравнивать |
| **Значение** | Одно найденное в статье число с показателем, единицей, страницей и цитатой |
| **Запись** | То, к чему относится значение: прибор или измерение в `solar`, конфигурация, набор данных, задача или эксперимент в `rag` |
| **Повтор** | То же число той же записи, найденное в другом месте статьи. Основным считается упоминание из таблицы, затем с рисунка, затем из текста |
| **Замечание** | Сигнал проверки о возможной ошибке: противоречие, значение вне разумного диапазона, расхождение с формулой и так далее |
| **Цитата** | Дословный фрагмент текста страницы, откуда взято число |
| **Референт** | Специалист, который подтверждает, исправляет или отклоняет значения и замечания |

## Шапка и общие элементы

Слева направо:

- **Vinity** — переход на список статей текущего набора.
- **Выбор набора** — область, набор и источник. Если у набора есть и результат системы, и эталон, они показаны отдельными строками. Синяя точка означает, что в наборе есть новые, ещё не открытые статьи. Внизу списка есть пункт **«Подключить новую область»**.
- **Вкладки**: Статьи, Все значения, Вопрос по статьям, Обзор, Качество, Области. Рядом с названием может стоять число: сколько статей или значений в наборе.
- **Солнце или луна** — переключение светлой и тёмной темы. Выбор запоминается.
- **Загрузить PDF** — выбор статей для загрузки и обработки.

Общие правила:

- У каждого экрана, статьи, значения и замечания есть свой адрес. Кнопка со скрепкой копирует ссылку, и коллега попадёт ровно туда же.
- Повторное нажатие на открытую вкладку возвращает в начало страницы. Справа у длинных страниц есть полоса прокрутки.
- Текст на страницах можно выделять мышью и копировать.
- Наведите курсор на бейдж или подчёркнутое слово, чтобы увидеть пояснение.
- Вёрстка подстраивается под ширину окна. На телефоне вкладки прокручиваются вбок, панели открываются поверх экрана.

## Статьи

Главный экран набора.

**Строка статистики**: сколько статей всего, в области, сколько значений и замечаний, сколько сканов (PDF без текстового слоя, текст для них распознаётся) и сколько значений проверено референтом.

**Поиск** по названию, ID или DOI и **фильтр**: все статьи, только с замечаниями, только вне области.

**Группы статей**:

| Группа | Что значит |
|---|---|
| Есть замечания | статья обработана, проверки нашли расхождения |
| Без замечаний | статья обработана, проверки пройдены |
| Не обработаны | значений ещё нет: статью не обрабатывал конвейер |
| Вне области | статья не про эту область, значения из неё не извлекаются |

**Бейджи у статьи**: число замечаний, «Скан», «Вне области», «Не обработана», «В очереди», «Обрабатывается · N с», «Ошибка обработки».

### Загрузка статей

Блок «Загрузка статей» справа (на телефоне сверху):

1. Выберите **область**, по профилю которой обрабатывать статью.
2. Перетащите PDF в рамку или нажмите **«Выбрать файлы»**. Можно несколько файлов сразу.
3. Статья попадает в набор «загруженные» выбранной области и сразу встаёт в очередь конвейера.
4. Статус виден в очереди и у статьи: «В очереди» → «Обрабатывается» (текст страниц → извлечение моделью → сборка таблиц и проверки) → готово. Когда значения появятся, придёт всплывающее сообщение, а страница обновится сама.

Если обработка не удалась, у статьи будет «Ошибка обработки» с причиной и кнопка **«Обработать заново»**. Не PDF и повреждённые файлы отклоняются с объяснением.

## Страница статьи

**Шапка**: название, бейджи («В области» или «Вне области», число замечаний, «Скан, текст распознан»), ID, год, число страниц, авторы, DOI и ссылка **«Листать страницы»**, которая открывает PDF на весь экран.

Строка **«Те же результаты»** появляется, если с другой статьёй набора совпадает несколько значений: метрика, число и единица. Обычно это значит, что одна статья приводит результаты другой, например как базовую линию. Нажмите на статью, чтобы открыть её.

**Строка статистики**: значений всего, из таблиц, из текста, с рисунков, повторов, замечаний, сколько проверено.

### Вкладка «Значения»

- **По записям / По показателям** — группировка значений. Название первой кнопки берётся из профиля: «По конфигурациям» в `rag`, по приборам в `solar`.
- **Показывать повторы** — повторы показаны бледнее и помечены «Повтор».
- **Только с замечаниями** — оставить значения, к которым есть замечания.
- **Сравнить с экспертами** доступно, если у набора есть эталон:
  - «Лишнее» — у экспертов этого значения нет;
  - «Сверх эталона» — у экспертов значения нет, но цитата дословно найдена на странице; возможно, эксперты его пропустили;
  - внизу списка — значения, которые нашли эксперты, а система нет.

Каждая строка показывает показатель, запись, агрегацию, страницу и место (таблица, рисунок или раздел текста), число, запись числа в статье и бейджи. Бейдж «Есть в D003» означает, что это же значение встречается в другой статье. Нажатие на строку открывает **карточку значения**.

Если статья не обработана, вместо списка будет пояснение и кнопка **«Обработать конвейером»**, если модель настроена.

### Вкладка «Замечания»

Все замечания к статье: правило, описание, числа с обеих сторон и цитаты. Снятые референтом замечания стоят в конце.

### Вкладка с записями

Название вкладки берётся из профиля, например «Конфигурации и наборы данных». Это таблицы записей статьи: конфигурации, наборы данных, задачи, эксперименты, приборы, материалы, измерения. Для каждой записи показаны её поля и сколько значений к ней относится.

### Вкладка «Сведения»

Название, год, DOI, авторы, область, причина «вне области», число страниц, из чего получен текст страниц (pypdf, PyMuPDF или распознавание скана), набор, источник значений и профиль извлечения.

## Карточка значения

Открывается справа или поверх экрана на узкой ширине.

- **Заголовок**: показатель и запись, к которой он относится.
- **Красные блоки** — замечания к этому значению. Ссылка «Разобрать замечание» открывает карточку замечания.
- **«Это же значение есть в другой статье»** — список статей и страниц, где совпадают метрика, число и единица.
- **Поля**:

  | Поле | Что показывает |
  |---|---|
  | Значение | число в единицах области |
  | В статье | как число записано в статье |
  | Нормализация | «в статье → у нас», если система меняла запись или единицу |
  | Примечание | пояснение, если оно есть |
  | Где | страница, таблица, рисунок или раздел |
  | Цитата | найдена ли цитата дословно и в каком варианте текста |

- **Страница PDF** с рамкой вокруг цитаты.
- **Цитата из статьи** текстом.
- **Подробнее**: как найдено (ячейка таблицы, предложение, подпись на рисунке), связанные записи, агрегация, происхождение (собственный результат статьи или из другой работы), повторы, есть ли значение у экспертов.

**Проверка референтом** (нижняя панель):

- **Подтвердить** — значение верное.
- **Исправить** — ввести правильное число. Исходное останется зачёркнутым рядом.
- **Отклонить** — значение ошибочное.
- **Отменить** — снять своё решение.
- Стрелки переходят к соседним значениям статьи.

Решения сохраняются на сервере и видны всем.

## Карточка замечания

- Описание замечания и правило, по которому оно найдено.
- Значения, которых касается замечание: числа, страницы и цитаты. Страницы с подсвеченными местами, причём красным выделено то, что спорно.
- **Подтвердить замечание** — ошибка в статье или в данных действительно есть.
- **Это не ошибка** — снять замечание, выбрав причину: разные условия измерения, округление в статье, число сверено со сканом или другая.

## Просмотр PDF

**Встроенный просмотр** в карточках:

- стрелки листают страницы;
- «Вернуться к цитате» — к исходной странице;
- лупы меняют масштаб;
- «Приглушить лишнее» затемняет всё, кроме выделения;
- квадрат в углу открывает страницу на весь экран.

**Полноэкранный просмотр** («Листать страницы» или квадрат в карточке):

- **«Все находки статьи»** — подсветить все значения и замечания на странице. Рядом указано, сколько их на текущей странице. Синяя рамка — значение, красная — значение с замечанием или само замечание.
- **Клик по выделению** открывает список: что это за выделение (значение с числом и местом или замечание с правилом и описанием). **«Подробнее»** закрывает просмотр и открывает карточку значения или замечания. Если на одной цитате несколько значений, в списке будут все.
- **Закрыть** или клавиша **Esc**.

Если цитату не удалось выделить, под страницей будет пояснение. Так бывает со сканами и подписями внутри рисунков.

## Все значения

Таблица всех значений набора с фильтрами.

| Фильтр | Что делает |
|---|---|
| Поиск | по статье, записи, числу и тексту цитаты |
| Показатель | один или несколько показателей. «Все показатели» раскрывает полный список |
| Откуда | таблица, рисунок, текст |
| Проверка | не проверено, проверено референтом, цитата не найдена |
| Диапазон | границы значения. Работает, когда выбран ровно один показатель, и тогда же появляется гистограмма распределения: нажмите на столбик, чтобы взять его границы |
| Показывать | только с замечаниями, без повторов |

**Столбцы таблицы**: статья, показатель, значение, как записано в статье, запись, агрегация, где (страница и место), статус (решение референта, замечания, повтор, «Есть в …», «Без цитаты»). Нажатие на заголовок столбца сортирует по нему, повторное — в обратном порядке. Нажатие на строку открывает карточку значения.

**Скачать CSV** выгружает таблицы набора в формате сдачи организаторов (zip).

## Вопрос по статьям

Вопрос на естественном языке по статьям текущего набора. Пример: «Какое самое высокое значение EM и в какой статье?»

Как это работает:

1. Система ищет подходящие фрагменты в тексте страниц статей и среди извлечённых значений.
2. Модель отвечает **только по этим фрагментам** и ставит номера источников в квадратных скобках: [1], [2].
3. Под ответом идут **источники**, на которые он ссылается: статья, страница и текст фрагмента. «Открыть страницу» показывает PDF с подсветкой, «Открыть значение» — карточку значения.

Остальные найденные фрагменты свёрнуты под ссылкой «ответ на них не опирается». Если в статьях нет данных для ответа, система так и скажет. Просьбы забыть правила или ответить не по статьям она не выполняет.

Если в `kt\local.properties` задан `rag.url`, вопрос уходит в модуль РАГ. Если модуль не ответил, система отвечает сама и пишет об этом над ответом. Строка «Ответил» под ответом показывает, кто именно ответил.

## Обзор

Графики по всем значениям набора. Какие графики показывать, задаёт профиль области:

| Область | График | Как читать |
|---|---|---|
| solar | **Напряжение против ширины запрещённой зоны** | каждая точка — прибор, у которого в статье есть и Voc, и ширина зоны поглотителя. Чем ближе к пунктиру, тем лучше прибор. Точка выше красной линии физически невозможна |
| solar | **Лучший КПД по статьям** | столбик — лучший образец каждой статьи |
| rag | **Лидеры по наборам данных** | лучшие конфигурации по метрикам внутри одного набора данных. Сравнивать честно только внутри одного набора данных и одной метрики |
| generic | **Значений по показателям** | сколько значений найдено по каждому показателю |

Наведите курсор на точку или столбик, чтобы увидеть подробности. Нажатие открывает карточку значения. Красным выделены значения с замечаниями.

## Качество

Пять вкладок, которые повторяют критерии кейса.

### Точность и полнота

Доступна, когда у набора есть и результат системы, и эталон экспертов.

- **Строгое / Мягкое сравнение**. Поля, по которым значение считается совпавшим с эталоном, задаёт профиль, а подсказка под переключателем их перечисляет. В `solar` мягкое сравнение смотрит показатель, число и происхождение, строгое — ещё агрегацию и страницу. В `rag` мягкое смотрит число, страницу и происхождение, строгое — ещё показатель и k метрики.
- **Все упоминания / Только основные**: считать каждое найденное место в статье или только основные значения без повторов.
- **Плитки**:
  - **точность** — какая доля найденного есть у экспертов;
  - **полнота** — какую долю значений экспертов нашла система;
  - **F1** — их среднее гармоническое, где 1 — идеально.
- **«Из чего складываются оценки»**: совпало с экспертами, лишние (нашли, а у экспертов нет), пропущено (есть у экспертов, а мы не нашли). Ниже — в скольких статьях область определена верно.
- **Таблица по показателям**: совпало, лишних, пропущено, точность, полнота, F1 по каждому показателю. Сортируется по любому столбцу нажатием на заголовок.

### Связь с местом в статье

Проверка так же, как у организаторов: цитата ищется дословно в тексте страницы (pypdf, PyMuPDF или распознавание скана).

- **Значения из таблиц и текста** — у какой доли найдена цитата. Цель — не меньше 95 %.
- **Все значения**, включая подписи на рисунках.
- **Без цитаты** — сколько значений без найденной цитаты, и их список.
- Разбивка по вариантам текста. «Ссылка на строку таблицы» значит, что для таблиц профиль допускает цитату вида «Table N, строка X».

### Нормализация

- **В целевых единицах** — у скольких показателей все значения приведены к единицам профиля.
- **Преобразовано значений** — сколько чисел система переписала: единица, запись `.204` → `0.204` и так далее.
- **Преобразования** — какие переводы выполнялись, с примером «в статье → у нас».
- **Единицы показателей** — целевая единица каждого показателя и сколько значений в ней.
- **Синонимы единиц** из профиля и **словари**: сколько полей таблиц содержат допустимые значения.

### Проверка достоверности

- **Совпало с экспертами** — сколько замечаний эталона система нашла сама.
- **Нашли только мы** — новые находки или ложные тревоги, решает референт.
- **Разобрано референтом** — сколько замечаний подтверждено или снято.
- **По правилам** — таблица: правило, сколько нашли, сколько у экспертов, сколько совпало. Сортируется по любому столбцу.

## Области

- **Система в цифрах** — статьи, страницы, сканы, значения, замечания, наборы и области по всем наборам.
- **Подключённые области** — карточка каждого профиля: описание области, таблицы с числом столбцов, показатели и единицы, включённые проверки, кнопки открытия наборов.
- **Подключить новую область** — загрузите `profile.json` и `rules.md`. Профиль проверяется сразу, и новая область появляется в списке и в выборе при загрузке статей. Ни одной строки кода писать не нужно. То же действие есть в выборе набора в шапке.
- **Сценарий демо** — заготовленные случаи из настоящих данных: замечание, нормализация, скан. «Открыть» ведёт прямо на нужное место, скрепка копирует ссылку.

## Проверки, которые делает сервер

Сервер сам проверяет результат системы при каждой загрузке набора, кто бы ни подготовил таблицы: конвейер, модуль РАГ или другой источник. Что проверять, задаёт профиль области.

| Проверка | Как работает |
|---|---|
| **Повторы** | значения с одинаковым ключом повтора из профиля (запись, показатель, агрегация, число) внутри статьи связываются с основным. Основным считается упоминание из таблицы, затем с рисунка. На эталоне `rag` сервер восстановил 18 119 из 18 177 повторов, размеченных экспертами |
| **Противоречия** (`contradiction`) | одна и та же величина одной записи в разных местах статьи записана разными числами, и разница больше округления. Граничные («<0.001») и приблизительные («~», «≈», снятые с графика) значения не сравниваются |
| **Несогласованные повторы** (`duplicate_consistency`) | значение помечено повтором, но расходится с основным по ключевым полям |
| **Метрика вне шкалы** (`metric_scale`) | значение выходит за шкалу своей единицы: например, доля больше 1 или процент больше 100. Шкалы задаёт профиль. Значения, записанные в статье со знаком («+5%», «−0.2»), — это изменения, их правило не трогает |
| **Метрика падает с ростом k** (`metric_k`) | для одной записи накопительная метрика вида Recall@k при большем k оказалась меньше, чем при меньшем. Какие метрики накопительные (recall, hit, success, coverage), задаёт профиль. Precision@k и NDCG@k так себя вести могут, поэтому не проверяются |
| **Проценты вместо процентных пунктов** (`percent_vs_points`) | изменение подписано «%», но число совпадает с разностью двух значений той же метрики того же набора данных, то есть это процентные пункты. В описании указано, каким было бы относительное изменение. Слова, по которым узнаются изменения (gain, improvement, drop…), задаёт профиль |
| **Одни и те же результаты в разных статьях** | если у двух статей совпадают метрика, число и единица хотя бы у трёх значений, они связываются. Значения получают бейдж «Есть в …», статьи — строку «Те же результаты» |

Замечания сервера стоят рядом с замечаниями конвейера. Номера у них начинаются с «S».

## Как читать цифры

- **Точность 0.80** — из 100 найденных значений 80 есть у экспертов. Остальные — лишние или «сверх эталона».
- **Полнота 0.40** — из 100 значений экспертов система нашла 40.
- **F1** — общая оценка: высокая, только если высоки и точность, и полнота.
- **Строгое сравнение** всегда не выше мягкого: требует совпадения большего числа полей.
- **Основные значения** — без повторов. Эту цифру разумно сравнивать с числом уникальных результатов в статьях.
- **«Сверх эталона с дословной цитатой»** — кандидаты в пропуски эталона: эксперты их не отметили, но число стоит на странице дословно.
- В области `rag` значения в **долях** и в **%** не пересчитываются друг в друга по имени метрики: используется шкала статьи (`.204` → 0.204 доли, `45.2%` → 45.2 %).

## Частые вопросы

**Статья «Не обработана», хотя PDF есть.** Конвейер ещё не обрабатывал её. Если модель настроена, на вкладке «Значения» статьи есть кнопка «Обработать конвейером».

**Цитата «не найдена в тексте страницы».** Для значений с рисунков это нормально: подписи на графиках часто отсутствуют в текстовом слое. Для сканов текст берётся из распознавания и может отличаться от оригинала.

**Вкладка «Точность и полнота» пустая.** У набора нет одновременно результата системы и эталона экспертов, сравнивать не с чем. Остальные вкладки работают.

**Вопрос по статьям отвечает «данных нет».** Значит, во фрагментах статей ответа нет. Система не додумывает. Переформулируйте вопрос ближе к словам статей, например с названием метрики или набора данных.

**Две статьи «совпадают по 30 значениям».** Скорее всего, одна статья приводит таблицу результатов другой как базовую линию. Это не ошибка извлечения, а связь между работами.
