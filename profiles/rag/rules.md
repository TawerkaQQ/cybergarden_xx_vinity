# Правила извлечения: Retrieval-Augmented Generation

Формат сдачи — `data/rag/submission_template/README.md` и `schema.json`, пример правильного ответа — `data/rag/dev_gold`, решения по каждой статье — `data/rag/dev_gold/coverage/*_audit.json`. Правила ниже — из шаблона и эталона.

## Что за корпус

- 21 статья dev (D001–D021), 90 test. Все 21 статья dev в области.
- Около 15 % PDF — синтетические сканы без текстового слоя: D002, D013, D021 в dev и 14 статей в test. Текст таких страниц получаем распознаванием.
- Эталон dev огромный: 37 616 значений. Из них 28 649 — одна статья D014. Без неё в среднем около 450 значений на статью: 65 % из таблиц, 25 % с рисунков, 10 % из текста.
- 4 733 конфигурации, 241 набор данных, 90 задач, 142 эксперимента. 479 разных названий метрик.

## Отбор статей

Система находит сведения во внешней коллекции и использует найденный контекст при формировании ответа; статья описывает конфигурацию и результаты оценки. Решаем по содержанию, а не по слову RAG в заголовке. Строка в `publications.csv` нужна для каждого PDF.

## Сущности

- **configurations** — каждая система, baseline, ablation-вариант и каждый генератор — отдельная конфигурация. Конфигурация «без RAG» тоже конфигурация (D016). Параметры не достраиваем по известным настройкам библиотек; диапазон — числовое поле пусто, диапазон в `note`. `top_k` — сколько документов извлекают, не k метрики.
- **datasets** — разные версии и разбиения, участвующие в разных сравнениях, не сливаем. Язык, разбиение и область — по статье.
- **tasks** — тип задачи свободным текстом.
- **experiments** — протокол оценки и условия сравнения. `sample_size` — размер оценочной выборки. Задержку и токены, зависящие от конфигурации, оформляем результатами, а не полем эксперимента.

## Значения (results)

1. Строка — одно значение одной метрики в одном эксперименте для одной конфигурации, набора и задачи. У основного результата заполнены `experiment_id`, `config_id`, `dataset_id`, `task_id`.
2. `metric_name` — как в статье. `metric_variant` — определение (token-level F1, macro, judge-based). `metric_k` — k для @k. `metric_direction` — `higher_is_better`, `lower_is_better`, `target` или пусто.
3. **Шкала — как в статье.** `.204` → `0.204` `fraction` (ноль слева добавляем, масштаб не меняем). `45.2%` → `45.2` `%`. Доли и проценты не пересчитываются по одному имени метрики. `raw_value` — запись как в статье, включая `≈` и знаки.
4. **Производные числа здесь записываются**, если статья их печатает: разности, относительные приросты, отношения — отдельной метрикой с понятным именем («EM difference vs EDP», «NDCG@5 relative improvement»). Проценты и процентные пункты не путать.
5. `aggregation` — только при явном указании; поле открытое: `mean`, `mean across queries`, `mean per question`, `upper_95CI`. Пусто у 88 % эталона.
6. `baseline_value` — только для сопоставимых задачи, набора, метрики, шкалы и протокола.
7. `cited` — число перенесено из другой работы, ссылка как в статье (`[24]`). Baseline, заново прогнанный авторами, — `primary`. Связи у `cited` пустые.
8. Каждое повторное упоминание — отдельная строка с `duplicate_of`. Поля повтора совпадают с основной записью: эксперимент, конфигурация, набор, задача, метрика, вариант, k, единица, значение (допускается более грубое округление), агрегация, выборка, происхождение. Если значения расходятся — это не повтор: обе записи и замечание.
9. `absent` — статья явно показывает, что значения нет (прочерк в таблице, «not calculated»), с пояснением. Не заполняем таблицу пустыми комбинациями «все метрики × все конфигурации».
10. `present_not_extractable` — значение обозначено, но его нельзя извлечь из PDF (например, только в supplementary).
11. **Рисунки.** Значение с явной подписью на графике — `extracted`, в `note` — как прочитано. Эталон также оцифровывает точки без подписей по векторным линиям PDF с калибровкой осей: `raw_value` с `≈`, точность и способ в `note`.

## Источник

- `source_page` — номер страницы PDF с 1, обязателен для извлечённого значения.
- `source_fragment` — **только буквальный текст страницы.** Запись «таблица 3, строка X» в цитату не пишем: таблицу указываем в `source_table`, строку и столбец — в `note`. В эталоне цитата для таблицы — текст строки, как его извлекает парсер.
- Цитата проверяется по тексту pypdf или PyMuPDF той же страницы, для сканов — по распознанному тексту. Нормализация проверки: NFKC, мягкие переносы, перенос слова через дефис на границе строк, пробелы.
- Для рисунка допустимы `source_figure` и пояснение в `note` без цитаты; такие значения проверяют вручную.

## Замечания (issues)

Названия правил открытые. Рекомендуемые: `metric_scale`, `metric_k`, `protocol_mismatch`, `normalization`, `contradiction`. В эталоне 134 замечания, почти все со своим названием: проценты против процентных пунктов, точность считывания графиков, расхождение рисунка и таблицы, неназванный генератор, разные знаменатели.
