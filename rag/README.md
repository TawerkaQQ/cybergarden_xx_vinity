# Поиск по документам и открытым источникам

Модуль ищет записи в SQLite FTS5, передаёт найденные фрагменты сервису ответов и выводит ссылки на источники. Поддерживаются связанные CSV-таблицы и текстовый слой PDF.

## Установка

Нужны Python 3.12 и SQLite с FTS5. Команды ниже выполняются из папки модуля.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` задайте адрес сервиса `CHAT_BASE_URL` и идентификатор профиля `CHAT_PROFILE`. `CHAT_BASE_URL` принимает базовый адрес и полный адрес с `/v1/chat/completions`. Для авторизации используется `CHAT_API_KEY`. Дополнительные поля запроса можно задать объектом JSON в `CHAT_REQUEST_OPTIONS`.

Каталог данных задаёт `RAG_DATA_DIR`. По умолчанию используется папка `data` рядом со скриптами. Путь к конкретному набору можно передать при индексации.

## Индексация и запросы

```bash
.venv/bin/python index.py --csv --data data/dev_gold
.venv/bin/python ask.py --csv "Какие параметры поиска указаны в статье D001?"
```

`--csv` загружает семь таблиц по схеме `csv_schema.json`. При индексации результаты связываются с публикациями, конфигурациями, датасетами, задачами и экспериментами. Источник содержит имя CSV, идентификатор записи и номер страницы, если он указан.

Для PDF запустите `index.py --data data/dev` и `ask.py` без флага `--csv`. Индексируется текстовый слой страницы. `--top-k` или `TOP_K` задаёт число фрагментов. По умолчанию CSV используют 8 фрагментов, PDF — 3.

## Выбор ответа

1. Сначала выводится ответ из локальной базы с учётом ранее одобренных веб-фрагментов.
2. Дополнительный ответ строится по тексту открытых страниц. Ссылки содержат URL и время получения.

В интерактивном терминале `2` добавляет процитированные фрагменты в `.approved-web.sqlite3`. В записи сохраняются текст, URL, название страницы и время получения и одобрения. Повторный выбор того же фрагмента сохраняет одну запись. `1` или Enter оставляет ответ из базы. Для работы с локальной базой используйте `--local-only`.

Публичный поиск по умолчанию использует DuckDuckGo Lite. Для собственного экземпляра задайте `SEARXNG_URL` и включите формат JSON. [API поиска SearXNG](https://docs.searxng.org/dev/search_api.html)

## Проверка извлечения PDF

`pdf_text_benchmark.py` сравнивает текст PyPDF и Tesseract с эталоном посимвольно, без учёта порядка символов. Для OCR нужны Tesseract с пакетом языка и утилиты Poppler. Число документов задаёт `--limit`. Без текстового слоя эталонный PDF можно указать через `--reference-pdfs`, а расшифровку рисунков — через `--graphics-reference`.

```bash
.venv/bin/python pdf_text_benchmark.py --pdf-dir data/dev --limit 5
.venv/bin/python benchmark.py run --extractor service
.venv/bin/python benchmark.py run --extractor rules
.venv/bin/python benchmark.py score .benchmark/dev-service/results.csv
```

`benchmark.py` сверяет извлечённые числовые записи с `data/dev_gold/results.csv`. Параметры `--gold`, `--only` и `--out` задают эталон, список публикаций и папку результата. Строгая оценка сравнивает публикацию, страницу, происхождение, число, название метрики и её `k`. В режиме `loose` сравниваются публикация, страница, происхождение и число. Ответы сервиса кэшируются по содержимому PDF и версии запроса.

`plot_benchmark.py` строит PNG из `scores.json`. Для графиков отдельно установите Matplotlib.

Файлы `.env`, локальные данные, индексы и результаты прогонов хранятся отдельно от публикуемого кода.
